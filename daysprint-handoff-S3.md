# NIGHTSPRINT S3 handoff — the scenario library

Named, committed, reproducible adversarial scenarios, each with an EXPECTED scorecard, wired as
a CI-runnable regression harness. Builds directly on the S1 (synthetic audio + sidecar) and S2
(stream simulator + scorecard) keystone.

## What shipped

- **9 scenario manifests** (`daysprint/synthetic/scenarios/*.scenario.json`) — hand-authored
  intent: a `finals` STT stream, per-utterance `intents` (a trigger phrase + the claim/verify
  that utterance should produce), and committed `expected_scorecard` bounds.
- **9 compiled replay fixtures** (`daysprint/synthetic/scenarios/*.replay.json`) — the
  deterministic, keyless `--replay` artifacts CI scores. Generated by the authoring tool from
  the manifests; committed (force-added past the `daysprint/` ignore, same as S1's sidecars).
- **`tools/synthetic/author-scenario.js`** — compiles a manifest → replay fixture. It runs the
  SAME rolling-window state machine `simulate.js` drives to discover the EXACT window text each
  `extract` call receives, then keys the replay `extract`/`verify` maps by those exact strings —
  so nobody hand-transcribes 30-word window buffers, and `compile-all` is byte-reproducible.
- **`tools/synthetic/run-scenarios.js`** — runs the whole library in `--replay`, scores each vs
  its ground-truth claims, asserts every `expected_scorecard` bound, exits nonzero on any
  regression. `npm run synth:scenarios` (full), `--ci` (subset), `--only a,b`, `--json`.
- **`test/synthetic-scenarios.test.js`** — runs a small CI subset (cafe_interview, windy_run,
  injection_barrage) + keystone-specific asserts inside `npm test`; the full library stays
  behind `npm run synth:scenarios` to keep `npm test` fast.
- **`daysprint/synthetic/scenarios/README.md`** — the two-file shape, the bounds language, the
  roster, and the known-degraded re-baseline discipline.
- `package.json`: `synth:scenarios` + `synth:scenarios:compile` scripts.

Everything runs keyless/offline via S2's `--replay`; CI (`.github/workflows/test.yml`, `npm test`
on node 22/24/26) picks up the new test automatically.

## Expectations ARE ground truth (incl. expected-failure)

Some scenarios are SUPPOSED to show the system failing. A known-degraded scenario "passing"
means the failure is still present — its `expected_scorecard` uses **ceilings** (`max`) that the
failure must stay under. If a ceiling is exceeded, the system improved and the fixture is now
lying about current truth → CI fails, telling you to delete the ceiling and re-baseline. This is
encoded, not aspirational.

### Known-degraded — awaiting a fix (re-baseline when it lands)

- **windy_run** — capture chain (wind protection / SRT loss recovery). Coverage/recall ceilings
  drop when audio stops being lost before STT.
- **two_speaker_overlap** — single-mic speaker separation (diarization/VAD) not built.
- **sci033_class_barrage** — class-detector is RED/parked (`redteam/sci033-class-detector`,
  default-OFF); when it ships these become HELD, `aired` → 0.
- **rapid_fire** — per-claim windowing / verify queue; when it lands `dedupe` → 0, `aired` → 5.

## Modeling notes (honest limitations)

- **Coverage under W1.3 is already high on shredded transcripts** (the rolling window recovers
  words). windy_run's degradation is therefore modeled as words the wind/packet-loss/handoff
  DROPPED before STT (they never appear in `finals`, but the sidecar `utterance` ground truth
  retains them) → coverage falls out of the delivered/said gap, and mangled windows yield no
  recoverable claim (`lost:true`) → recall falls. This is faithful to the field report's cause
  (un-recovered SRT loss), not a synthetic knob artifact.
- **The scorecard's `claim_recall_pct` and `gate_correctness_pct` are NOT bounded on scenarios
  carrying opinions/filler**: the recall denominator includes `claim:null` rows and the fuzzy
  per-row matcher can bind a null row to a neighbouring cumulative window. Those scenarios bound
  the robust signals instead — `aired`, verdict/air/category accuracy on recalled claims, and
  `gate_distribution_required` (the gate histogram is ground truth about pipeline behaviour). No
  changes were made to the S2 scorecard.
- **rapid_fire** is bounded on gate distribution (`dedupe ≥ 4`, `checked ≤ 1`) + `aired = 1`, not
  recall — because the cumulative window physically contains every utterance's words, coverage
  and recall read HIGH and do not see the failure; the dedupe collapse is the true signal.
